# 训练与提交 · 结论（P2 / P3 / P4 与 TAESD）

评估集：P0，177 对 held-out（`$CSIG/data/eval_p0`）。指标是**保留增益**
`(p_out − p_lq)/(p_gt − p_lq)`，其中 `p = 13.674·TOPIQ-FR + 4.477·MANIQA − 5.731`。
全部逐样本原始结果在 `docs/eval_p0/`。

---

## 1. 最要紧的一条：线上提交的一直是未微调的基线

`submit/model_dir/runner.py` 的 `export_weights` 里，LoRA 路径写死成
`src/HYPIR_sd2.pth` —— 官方**未微调**权重。所以 `submit/model_dir/` 里打包的、
以及第 9 次提交上线的，是 **19.0%** 的基线模型，P2/P3 的训练收益一次都没进过提交包。

换成 P2@7000 就是 **19.0% → 45.6%**。按已解出的评分公式
`综合分 = 感知分 × 加速比^0.204`，画质线性进分，这个量级远超任何速度优化。

已加 `--lora` 参数。微调 checkpoint 与官方权重结构一致（514 tensor / 257 模块 /
同样 key 命名 / fp32），`LORA_SCALE=1.0` 对得上 `lora_rank=256`，合并逻辑不用改。

## 2. 权重对比

| 权重 | FR | NR | p_out | 保留增益 |
|---|---:|---:|---:|---:|
| 官方基线（第 9 次提交用的） | 0.4012 | **0.4371** | 1.711 | **19.0%** |
| P2 @6000 EMA | 0.6080 | 0.2800 | 3.836 | 44.7% |
| **P2 @7000 EMA** | 0.6124 | 0.2826 | 3.909 | **45.6%** |
| **P3 @8000 裸** | **0.6140** | 0.2736 | 3.890 | **45.4%** |
| P3 @8000 EMA | 0.6089 | 0.2736 | 3.820 | 44.5% |
| P2 @7000 裸 | 0.5955 | 0.2662 | 3.604 | 41.9% |

**训练全程是在拿 NR 换 FR，而这是对的** —— 未微调基线的 MANIQA 最高（0.4371）
综合分却最低，因为代理公式里 FR 的权重是 NR 的 3 倍。基线→P2@7000：
FR 涨 0.2112（折 +2.888），NR 跌 0.1545（折 −0.692），净 +2.196，这就是全部收益。

## 3. P2 与 P3 打平，但趋势相反

P3@8000 裸 vs P2@7000 EMA，配对 t 检验 **p = 0.629，无显著差异**
（均值差 −0.019，95% CI [−0.095, +0.058]，P3 胜 91/177）。

但两者所处的阶段完全不同：

- **P2 已过峰值**：裸权重 6000 步 42.9% → 7000 步 41.9% 在退，是 EMA 在替它守住早期权重
- **P3 还没收敛**：EMA 仍在稳定爬升（7000 → 9000 步：44.0 → 44.2 → 44.5 → 45.0）

所以 P3 继续训还能涨，P2 不会。已续训到 16000 步。

**一处需要纠正的判断**：8000 步时裸权重 45.4% 反超 EMA 44.5%，我据此说过「还没收敛」。
9000 步的数据推翻了这个依据——裸权重掉回 43.3%，重新落到 EMA 之下。**那个反超是振荡，
不是趋势**。GAN 的裸权重本来就会大幅振荡，单点反超说明不了方向。结论仍成立，
但依据是 EMA 的稳定爬升，不是裸权重的一次反超。

**读曲线的规则**：`ema_decay=0.999` 时间常数约 1000 步，早期 checkpoint 的 EMA
被初始权重（正好是 19.0% 的基线）主导 —— 500 步时 EMA 只有 25.1% 而裸权重已到 38.5%。
**早期看裸权重，中段之后看 EMA。** 不要用「裸权重反超 EMA」判断收敛——
裸权重在 8000/9000 步之间从 45.4% 掉到 43.3%，振荡幅度比 EMA 两千步的涨幅还大。

## 5. 提交包已端到端验证

打包版 runner 在同一 177 对上跑出 **45.6%**，与训练侧 SD2Enhancer 完全一致
（p_out 3.908 vs 3.909，FR/NR 逐位相同）。

两条路径的**图像**并不逐位一致 —— runner 把 temb 折进 `conv1.bias`、融了 QKV、
把 nearest+conv 折成 ConvTranspose，实测 PSNR 42–47 dB。所以「打包有没有打坏」
只能用分数验证，不能用 dB 推。`eval_p0.py --runner-dir` 就是干这个的。

**两个会静默改坏提交的坑，已堵**：

- `export_weights` 用 `DEFAULTS` 重写 `config.yaml`，会把特意钉成 `cuda` 的
  `op_backend` 变回 `auto` —— 后端一变时延就变，而时延进分。改成已存在就不覆写。
- LoRA 路径写死官方权重（见 §1）。

## 6. 机器与链路

- **本机 ↔ hyper00 只有 ~89 KB/s**（实测裸 ssh 60 秒传不完 100 MB）。
  2.58 GB 的权重传到本地要 7.7 小时，**提交包必须在 hyper00 上打、从 hyper00 上传**。
- hyper00 → 阿里云 **98.6 MB/s**，3 GB 的包上传约 30 秒。
- hyper00 ↔ hyper01 私网 ~800 MB/s（这是之前记的那个数，别和上面混了）。

## 7. P4（v2 宽退化）也败给未微调基线 —— 根因是训练目标与评分目标不一致

P4 换了宽支撑集的退化配方 v2（加真实重采样链路、全面放宽区间）。真实退化闸门上：

| 权重 | FR | NR | p_out | 真实对保留增益 |
|---|---:|---:|---:|---:|
| 基线（未微调） | 0.4198 | **0.4236** | 1.906 | **13.5%** |
| P4 @500 | **0.4378** | 0.3547 | 1.843 | 12.7% |
| P4 @1000 | 0.4344 | 0.3072 | 1.584 | 9.3% |
| P4 @2500 | 0.4185 | 0.2826 | 1.257 | 5.1% |
| P4 @5000 | 0.4128 | 0.2892 | 1.208 | 4.4% |
| P3（v1 窄配方） | 0.3913 | 0.2776 | 0.862 | −0.1% |

v2 比 v1 好（−0.1% → 12.7%），但**从第 500 步起单调下滑**，始终没超过基线。

**根因在分量里。** 看 @500 相对基线：

```
p = 13.674·FR + 4.477·NR − 5.731
FR 0.4198 -> 0.4378   涨 +0.018  ->  p +0.246
NR 0.4236 -> 0.3547   跌 −0.069  ->  p −0.308
                                      净 −0.062
```

**微调确实提升了保真度**（FR 超过基线），但赚到的 TOPIQ 不够赔掉的 MANIQA。

而训练损失是 `L2 + LPIPS + GAN` —— 三项全在优化保真度，**没有一项管 MANIQA**，
而 MANIQA 在评分代理里的权重是 4.477。训得越久模型对图像动手越多，
在真实的轻度退化上就越亏。这解释了 P2/P3/P4 三轮为什么无一例外败给基线。

**要继续训的话方向已明确**：把 MANIQA 加进损失（它是可微 CNN，可直接当感知损失），
或大幅提高 `P_CLEAN`（现在只有 4%）——真实退化很轻，模型该学的是「少动手」。

## 8. 唯一有正向证据的改动：换 VAE（不碰模型权重）

| 方案 | 真实对 | P0(40张) | V100 单 tile | 提速 | 预估分 |
|---|---:|---:|---:|---:|---:|
| SD/SD（现状） | 13.5% | 22.0% | 85.78 ms | 1.00× | 44.0 |
| **SD/TAESD** | **15.2%** | **24.4%** | 50.78 ms | **1.69×** | **52.3** |
| TAESD/SD | 10.3% | 18.3% | 68.31 ms | 1.26× | 40.1 |
| **TAESD/TAESD** | **16.0%** | 22.0% | 42.11 ms | **2.04×** | **56.0** |

TAESD 解码器**又快 8 倍、画质还更好**：FR 几乎不变（0.4198→0.4197），涨的是 NR
（0.4236→0.4528）。蒸馏解码器输出偏「干净锐利」，正好是 MANIQA 吃的那一套——
与 §7 的病征恰好相反。

`TAESD/SD` 混搭最差，印证了自编码往返 PSNR 的观察（SD+TAE 28.87 / TAE+SD 24.77 /
TAE+TAE 29.94）：TAESD 的编解码是共同适配的，拆开用更亏。

**注意 TAESD/TAESD 的证据不一致**：真实对 +2.5 点，P0 上却是 0.0 点，而真实对只有
3 张。SD/TAESD 在两个集合上都正向，是稳妥选择。

### 两个差点让结论完全错误的陷阱

- **enhance 不走 `_infer_tile`**。它是三段独立 tiled 流程（tiled encode → tiled UNet →
  tiled decode），调 `self.vae.{encode_moments,sample_latent,decode}`。只 patch
  `_infer_tile` 的话四种组合输出**逐位相同**（实测 200 dB），看上去像「TAESD 零画质代价」。
- **`dec_sd = lambda z: r.vae.decode(z)` 会自递归**：patch 覆写 `r.vae.decode` 之后
  它调用自己。异常被 `2>/dev/null` 吞掉，表现为跑到表头就没输出。
